# AI Agent Instructions for MDSeeker Windows Desktop Development

This document is the source of truth for AI agents working on the MDSeeker desktop project. Read it before inspecting, generating, or modifying code. Existing project code and explicitly approved developer decisions take precedence over assumptions.

## 1. Core Philosophy and Stack

- Build a lightweight, blazing-fast, Windows-first Markdown viewer.
- App name: `MDSeeker`. Application ID: `com.devson.mdseeker`. Distribution: Windows installer and portable executable.
- Stack: Tauri 2, Rust (2021 edition), React 19, TypeScript, Vite, Tailwind CSS, Custom Windows 11 Fluent-inspired design system, Zustand, pulldown-cmark, syntect, CodeMirror 6, Mermaid, KaTeX, and pnpm.
- The backend is written in Rust (`src-tauri`). The frontend is React + TypeScript (`src`).
- Clear ownership boundary: Rust owns all filesystem operations, document loading, Markdown parsing, syntax highlighting, metadata extraction, Windows OS integration, and security validation. React owns the presentation layer, document tabs, reader view, source viewer, settings UI, and toolbar.
- Do not duplicate Markdown parsing between Rust and React. React displays parsed structures, ASTs, or validated sanitized output generated by Rust.
- Never expose unrestricted filesystem access to the frontend.
- No hallucinations: use APIs, dependencies, endpoints, and structs that exist in the project or have been verified against authoritative Tauri 2 and Rust documentation. Inspect files or ask when uncertain.
- Keep explanations short, precise, and technically accurate.
- Begin each new coding-agent session with the words `Hey Devson`.

## 2. UI and Fluent Design System

- Custom Windows 11 Fluent-inspired design system: Mica-inspired surfaces, Acrylic-inspired translucent layers, subtle borders, restrained elevation shadows, and Segoe UI Variable typography.
- Jetpack Compose / WinUI 3: This application uses Tauri 2 + React + WebView2. Never claim to implement actual WinUI 3 controls.
- Theme support: Light, Dark, and System modes. Persist user preferences in local storage (`mdseeker-theme`) and listen dynamically to OS color scheme changes (`prefers-color-scheme: dark`).
- Keep components focused and reusable. Separate visual rendering from state orchestration and IPC.
- State management: Use Zustand for global UI and presentation state.
- Avoid unnecessary re-renders. Never perform heavy text parsing, syntax highlighting, or file I/O inside React render cycles.
- Provide accessible labels, semantic ARIA roles, high color contrast, visible keyboard focus indicators (`focus-visible:ring-2`), and reduced-motion support (`@media (prefers-reduced-motion: reduce)`).
- Ensure narrow-window responsiveness down to the configured minimum dimensions (640x480).

## 3. Application Architecture and Responsibility Boundaries

Follow the established project structure; do not restructure without concrete reason. Maintain clear responsibility boundaries:

- `src-tauri/src/`:
  - `commands.rs`: Typed Tauri commands returning structured, serializable models (`serde::Serialize`, `serde::Deserialize`).
  - `lib.rs`: Tauri builder, plugin initialization, handler registration, and unit tests.
  - `main.rs`: Windows subsystem entrypoint (`mdseeker_lib::run()`).
- `src/`:
  - `components/window/`: Custom title bar, drag region (`data-tauri-drag-region`), and native window controls.
  - `components/tabs/`: Tab bar, tab items, close actions, and horizontal overflow.
  - `components/toolbar/`: Reader toolbar, view mode toggles, search, and appearance menus.
  - `components/sidebar/`: Document outline and navigation sidebar.
  - `components/workspace/`: Main document reader, source viewer, and empty workspace.
  - `components/status/`: Bottom status bar with document info, stats, and view mode indicators.
  - `components/common/`: Reusable primitives (`IconButton`, `Tooltip`, etc.).
  - `stores/`: Zustand stores (`uiStore`, etc.).
  - `styles/`: Centralized Fluent design tokens (`fluent-tokens.css`, `themes.css`, `components.css`, `global.css`).

Rules:
- Rust commands must return explicit `Result<T, String>` or structured error objects.
- Validate, sanitize, and canonicalize all file paths in Rust before opening.
- Sanitize rendered HTML before presenting in React to prevent XSS. Validate external links and local resource references.
- Interactive window controls must be flagged with `tauri-no-drag` to prevent accidental window dragging.

## 4. Rust and Code Quality

- Rust 2021 edition is the exclusive backend language.
- Use explicit error handling (`Result<T, E>`). Never use `unwrap()` or `expect()` in command handlers where runtime errors can occur. Convert errors into user-friendly descriptions.
- Keep MSVC debug symbols disabled (`debug = 0` in `[profile.dev]` and `[profile.test]`) to prevent multi-gigabyte `.pdb` generation from exhausting disk space and triggering linker error `LNK1140`.
- Catch specific I/O and parsing errors. Never swallow errors silently.
- Avoid unnecessary memory allocations, large buffer clones, and redundant string copies.
- Follow existing Cargo and version conventions. Verify compatibility before adding dependencies.
- Prefer clear names, small functions, and single-responsibility modules.
- Do not add the Unicode box-drawing character `─` anywhere in code files.

## 5. Windows Integration, Security, and Permissions

- Tauri 2 permissions: Grant only explicit permissions required for desktop capabilities in `src-tauri/capabilities/default.json`.
- File associations: Handle `.md` and `.markdown` files passed via CLI arguments or Windows File Explorer double-click.
- Single-instance behavior: Forward second-instance CLI arguments to the running primary instance and bring the window to focus. Never launch duplicate application windows.
- Default app preferences: Never silently override Windows default-app preferences.
- Local resource access: Restrict local resource loading to the directory of the currently open document. Prevent directory traversal attacks (`../`).
- Link handling: Open external web links (`http://`, `https://`) securely in the user's default browser via Tauri's opener plugin, not inside the WebView.

## 6. MDSeeker Product Rules & Specifications

- Three viewing modes:
  - Reading mode (rendered Markdown reader).
  - Source mode (read-only CodeMirror 6 source inspection).
  - Split mode (synchronized dual-pane reading and source view).
- Multi-document tabs:
  - Support multiple open documents.
  - Tab switching, closing, and reordering.
  - Duplicate-path detection: re-selecting an already open file focuses its existing tab rather than creating a duplicate.
  - Tab overflow with horizontal scroll support.
  - Recent documents list.
- Markdown features:
  - CommonMark standard compliance.
  - GFM tables, task lists, and autolinks.
  - Headings, blockquotes, nested lists, images, and horizontal rules.
  - Syntax highlighted code blocks via `syntect`.
  - YAML/TOML frontmatter parsing and display.
  - Mermaid diagrams and KaTeX math expressions.

## 7. Testing and Verification

- Add/update unit tests for all meaningful behavior changes.
- Frontend tests: Run Vitest with Happy-DOM (`pnpm test`).
- Backend tests: Run Cargo test (`cargo test --manifest-path src-tauri/Cargo.toml`).
- Compiler checks: Run TypeScript check (`pnpm build` or `tsc --noEmit`) and `cargo check`.
- Before declaring a phase complete, execute all builds and test commands. Report commands and results accurately.
- Never claim a test passed without actually executing it.

## 8. Documentation and Changelog

Maintain `update_details.md`:
- After every completed task, bug fix, optimization, architecture change, or feature, append an entry at the end. it should be properly marked down.
- Do not rewrite the whole file for routine updates.
- Include date and time.
- Use:
  - **Issue:** Brief description.
  - **Type:** Error, Bug, UI, Performance, Architecture, Security, or Feature.
  - **Solution:** Maximum 10 lines.
- Append exactly `---` on a new line after each entry.
- Do not add conversational filler.

## 9. Version Control and Repository Safety

- Do not commit, push, create releases, or publish artifacts unless explicitly instructed.
- STRICT: Do not modify any `.gitignore` file; the developer manages these manually.
- Do not delete, overwrite, or mass-reformat unrelated files.
- Inspect existing implementation before changing architecture or configuration. Explain potentially breaking changes.
- Keep changes scoped to the active task and preserve unrelated developer changes.

## 10. Agent Workflow and Phase Roadmap

Development is divided into 12 sequential phases:
1. Project initialization *(Completed)*
2. Fluent UI foundation *(Completed)*
3. Rust file management
4. Markdown parsing engine
5. Markdown reader
6. Source inspection mode
7. Syntax highlighting and advanced rendering
8. Multi-document tab management
9. Windows integration
10. Settings and customization
11. Reliability and performance
12. Packaging and release

Rules:
1. Inspect relevant files and current implementation before editing.
2. Identify the smallest set of files that needs to change.
3. Check existing conventions and dependency versions.
4. Implement ONLY the requested phase; do not silently proceed to future phases.
5. Build and test affected code (TypeScript, Vite, Cargo).
6. Fix regressions introduced by the change.
7. Append the required `update_details.md` entry.
8. Summarize changed files, behavior, verification results, and limitations in the Phase Completion Report.
9. Wait for developer approval before starting the next phase.

If a requirement is ambiguous or depends on an unconfirmed policy, ask one focused question rather than inventing a rule.
